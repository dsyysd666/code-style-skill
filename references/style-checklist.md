# 风格维度清单：帮用户说出没想到的偏好

用户通常只能说出"我想看得懂"这一层。下面这张表用来**逐项追问**，把模糊感觉逼成具体规则。
用法：挑 5～6 项用户最可能有想法的问，不要 14 项全问一遍（会把小白问跑）。

---

## 追问话术模板

> 还有几个小地方确认一下，你挑着答，没想法的说"随便"就行：

然后按优先级问。

---

## 高优先级（几乎人人都有偏好）

| # | 维度 | 问法 | 常见答法 → 规则 |
|---|---|---|---|
| 1 | 变量长度 | "变量你喜欢 `用户年龄` 这种长名，还是 `age` 这种短的？" | 长 → 完整单词；短 → 允许缩写 |
| 2 | 注释量 | "注释是每行都要，还是只在关键地方？" | 每行 → A 型；关键处 → C 型 |
| 3 | 一行几件事 | "能接受 `a = b = c = 1` 这种写法吗？" | 不能 → 一行一事、不链式 |
| 4 | 花哨语法 | "有几种简化写法（比如一行搞定循环的），你想学还是先不用？" | 先不用 → 列入禁用语法 |
| 5 | 出错时想看到什么 | "代码报错时，你希望它告诉你什么？" | 哪一行 → 步骤编号注释；什么值 → 打印变量；怎么改 → 三段式报错 |

## 中优先级（问 1～2 个就够）

| # | 维度 | 问法 |
|---|---|---|
| 6 | 函数长短 | "一个函数你希望多长？二十行以内，还是能接受五六十行？" |
| 7 | 缩进与空行 | "缩进 4 空格行吗？函数之间要不要空行隔开？" |
| 8 | 分步骤 | "要不要在代码里写 `# 第1步` `# 第2步` 这种编号？"（对自学排查很有用） |
| 9 | 打印风格 | "调试用的打印，你想看 `12` 这种裸值，还是 `平均值是 12` 这种带说明的？" |
| 10 | 英文还是中文 | "变量名用英文，还是你能接受拼音 / 中文？"（中文变量名 Python 可行，其他语言多为不建议） |

## 低优先级（用户提了再记）

| # | 维度 | 说明 |
|---|---|---|
| 11 | import 位置 | 全部放文件头 / 用到再导入 |
| 12 | 字符串引号 | 单引号还是双引号 |
| 13 | 末尾逗号 | 多行列表要不要留尾逗号 |
| 14 | 文件组织 | 一个文件塞完 / 按功能拆多个文件 |

## 从用户的话里反推规则（重要）

用户不会说术语，但要学会听懂。对照表：

| 用户原话 | 真实含义 | 写进档案的规则 |
|---|---|---|
| "我看不懂缩写" | 命名要自解释 | 禁用缩写与单字母，变量用完整单词 |
| "代码挤在一起我头晕" | 需要留白 | 一行一事、逻辑块之间空一行、运算符两侧空格 |
| "出错我不知道哪坏了" | 缺可观测性 | 步骤编号注释 + 每步打印中间值 + 三段式报错 |
| "我想边看边学" | 需要解释 | 每行注释写"在做什么"，代码后附人话版讲解 |
| "要交作业 / 给别人看" | 需要规范感 | 文件头注释 + 函数文档字符串 + 类型标注 |
| "我老是忘括号 / 缩进" | 需要视觉辅助 | 括号成对写再回填内容；缩进严格 4 空格；嵌套不超两层 |
| "我改完总引出新 bug" | 需要隔离 | 每步独立成行、不用链式、函数单一职责 |
| "跟我现在写的一样就行" | 要照抄现有习惯 | **请用户贴一段自己写的代码**，从中提取规则（最准的办法） |

---

## 最准的一招：让用户贴自己的代码（快通道）

如果用户手上有自己写过的代码，**直接让他贴 20 行过来**，比问十个问题都准。
从这段代码里提取：命名长度、缩进、注释习惯、括号风格、空行习惯、报错写法，直接填档案。
提取完把规则念给用户确认："我看到你习惯这样写，对吗？"

提取时逐项对照并填写档案：

| 观察点 | 从代码里看什么 | 填入档案哪一节 |
|---|---|---|
| 变量名 | 全名还是缩写，长度，是否用下划线 | 命名规则 |
| 函数名 | 是否 `动词_名词`，驼峰还是下划线 | 命名规则 |
| 缩进 | 2 空格 / 4 空格 / tab | 格式规则 |
| 一行几件事 | 有没有链式、复合表达式 | 格式规则 |
| 注释 | 有没有、密度、写"是什么"还是"为什么" | 注释规则 |
| 括号/空行 | 括号位置、函数间空几行 | 格式规则 |
| 报错写法 | 是否打印、信息里带什么 | 排查友好规则 |
| 语法习惯 | 用不用推导式/三元/ lambda | 结构规则 + 硬规矩 |

提取的只是"用户已有的习惯"，用户没写过的地方（如异常处理）仍需按 SKILL.md 步骤 4 追问补齐，不要凭空假设。
